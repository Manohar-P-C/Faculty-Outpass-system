## Slide 2: Problem Statement
**Title:** The Challenge
* **Manual Processes:** Existing paper-based or manual gate pass systems are time-consuming and inefficient.
* **Lack of Real-time Tracking:** Difficult for management to track who is currently off-campus during working hours.
* **Communication Gaps:** Delays in getting physical approvals from HODs or Principals.
* **Record Keeping:** Maintaining and retrieving historical data of faculty exits is tedious.

---

## Slide 3: Our Solution
**Title:** Introducing the Faculty Exit Monitoring System
* A centralized web-based application designed to digitize and automate the faculty exit workflow.
* Connects Faculty, Head of Departments (HODs), the Principal, and Campus Security on a single platform.
* Ensures secure, transparent, and swift processing of exit requests during college hours (8:00 AM - 4:00 PM).

---

## Slide 4: Key Features (Part 1)
**Title:** Key Features
* **Role-Based Access Control (RBAC):** Dedicated, secure dashboards for Faculty, HODs, Principal, and Security.
* **Streamlined Approval Workflow:** 
  * Faculty submits a request.
  * HOD reviews and approves/rejects.
  * Principal gives final approval.
* **Constructive Feedback:** Approvers can provide specific reasons if an exit request is rejected.

---

## Slide 5: Key Features (Part 2)
**Title:** Advanced System Capabilities
* **Smart Time Restrictions:** Exit requests can only be made within official college hours (8 AM - 4 PM).
* **Automated Email Notifications:** 
  * Real-time status updates for approvals/rejections.
  * **10-Minute Pre-slot Reminders** sent to faculty before their approved exit time.
* **Security Integration:** Real-time dashboard for security personnel to verify approved exits at the gate.
* **Automated Maintenance:** Monthly automatic resets of exit requests to maintain a clean database.

---

## Slide 6: System Architecture / Workflow
**Title:** How It Works
1. **Request:** Faculty logs in and submits an exit request with date, time, and reason.
2. **First Level Approval:** HOD is notified and reviews the request on their dashboard.
3. **Final Level Approval:** Principal reviews HOD-approved requests for final sign-off.
4. **Notification:** Faculty receives an email update about the decision.
5. **Exit Verification:** Security verifies the approved status at the gate when the faculty leaves.

## Slide 7: Technology Stack
**Title:** Technologies Used
* **Frontend:** HTML, CSS, JavaScript (Responsive UI for mobile and desktop)
* **Backend:** Python with Flask Framework
* **Database:** MySQL (Cloud-hosted via Aiven)
* **Deployment:** Hosted securely on Render cloud platform
* **Other Tools:** SMTP for Email Automation

## Slide 8: Benefits & Impact
**Title:** Why This System Matters
* **Enhanced Security:** Only authorized exits are permitted; security has a real-time log.
* **Time Efficiency:** Eliminates the need to search for HODs/Principals for physical signatures.
* **Transparency:** Faculty can track the exact status of their requests.
* **Eco-Friendly:** Completely eliminates paper-based gate passes.
* **Data-Driven:** Provides management with clear records of faculty movement.
